# ADR 0002: Authentication, Token Rotation, and Authorization

## Status

Accepted.

## Context

Services need a secure, stateless access token mechanism paired with revocable session continuity and resistance to timing and replay attacks.

## Decision

1. **Passwords:** Hash with `argon2id` encoded in standard PHC format (`$argon2id$v=19$m=...,t=...,p=...$salt$hash`) with a 16-byte random salt and `subtle.ConstantTimeCompare`. Unknown-user login attempts run `VerifyDummy` against a precomputed hash so response times do not leak email existence. Unknown user, wrong password, and disabled accounts all return the same `ErrInvalidCredentials`.
2. **Access tokens:** Use symmetric PASETO `v4.local` (`aidanwoods.dev/go-paseto`) carrying `sub` (user UUID), `role`, `jti`, `iat`, `nbf` (`SetNotBefore(issuedAt)` to satisfy `paseto.ValidAt`), and `exp`.
3. **Refresh tokens:** Generate 32 random bytes (base64url-encoded on the wire) and store only their `SHA-256` digest in `refresh_tokens`. Every `/v1/auth/refresh` call locks the row (`FOR UPDATE`), rotates the token within the same `family_id`, and issues a successor. Presenting an already-rotated token immediately revokes the entire token family and commits that revocation.
4. **Authorization:** Middleware (`RequireAuth`, `RequireRole`) attaches the typed `Principal` to `context.Context` and handles coarse role gates. Resource ownership (such as member vs. admin access to orders) is enforced in the service layer.
