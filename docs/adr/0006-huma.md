# 0006. Huma v2 for Typed HTTP Operations and Code-First OpenAPI

Date: 2026-10-16
Status: Accepted

## Context

Prior to this decision, HTTP endpoints were registered directly on Go 1.22's `http.ServeMux` using manual request body decoding (`httpx.Decode`), imperative parameter parsing (`strconv.ParseInt`), manual error mapping, and hand-maintained OpenAPI specifications. This introduced duplicate maintenance burden between Go structs and OpenAPI schemas, leading to potential specification drift, uneven parameter validation across routes, and missing documentation for edge cases.

## Decision

We adopt `github.com/danielgtaylor/huma/v2` (`v2.39.1`) as a bounded HTTP adapter:

1. **Strict Architectural Boundary**: Feature packages (`internal/users`, `internal/orders`, etc.) NEVER import `github.com/danielgtaylor/huma/v2` directly. All Huma types (`API`, `Operation`, `Middlewares`, `Context`, `Param`, `Schema`) and registration functions are re-exported through `internal/platform/httpx`. This boundary is statically enforced by `depguard` in `.golangci.yml`.
2. **Code-First OpenAPI 3.1**: OpenAPI specification generation is derived from typed Go structs and struct tags (`format`, `minimum`, `maximum`, `doc`). Manual spec maintenance is replaced by `cmd/openapi`, `make openapi`, and `make openapi-check`.
3. **Unified RFC 9457 Error Model**: We configure Huma (`SetupHumaErrorModel`) to produce `*httpx.Problem` responses conforming to RFC 9457 for all client errors (validation, authentication, domain errors) with field-level details, while 5xx internal errors suppress internal details.
4. **$schema Suppression**: By setting `config.CreateHooks = nil`, we disable Huma's default response link transformer, ensuring JSON response payloads remain standard and clean without unwanted `$schema` fields.
5. **Middleware Adaptation**: Standard `func(http.Handler) http.Handler` middlewares (rate limiting, authentication, idempotency) are cleanly adapted into Huma operation middlewares via `httpx.AdaptMiddleware`.
6. **Zero Impact on Domain Purity**: Domain entities, use-case services, repositories, and River jobs remain 100% free of Huma or HTTP dependencies.

## Consequences

- Exactly one new direct dependency: `github.com/danielgtaylor/huma/v2`.
- OpenAPI documentation stays strictly synchronized with handler code and CI verifies drift via `make openapi-check`.
- Low measured runtime overhead (~826 ns and 5 allocations per request compared to bare `net/http`).
- Complete uninstallation path preserved without touching domain logic.
